# 局域网文件互传 · 开源库与方案调研

> 目标约束：**使用简便 + 免安装（绿色单文件）**
> 调研时间：2026-10-20

---

## 一、结论速览

| 判断 | 内容 |
|---|---|
| **最佳技术栈** | Go + 单 exe（`CGO_ENABLED=0`），UI 用 WebView2 或 Fyne |
| **最佳协议** | 直接实现 **LocalSend Protocol v2**（Apache-2.0，公开规范） |
| **不要做的事** | ① 不要 fork LANDrop（已闭源）② 不要上 QUIC（局域网反而更慢）③ 不要用 Electron/Python 打包 |
| **最大杠杆** | 协议兼容 LocalSend ⇒ 你的软件能和已有 500 万+ 装机量互传，零成本获得生态 |
| **最该补的短板** | LocalSend 协议**没有断点续传**，这是你唯一值得做的差异化功能 |

预期产出：**单文件 ~10 MB、双击即用、无需管理员权限、传输速度吃满千兆（110 MB/s 级）**。

## 二、现成开源项目横评

### 2.1 可复用性分级

| 项目 | 语言/UI | 许可 | 活跃度 | 体积 | 可复用性 | 结论 |
|---|---|---|---|---|---|---|
| **LocalSend** | Flutter + Rust | **Apache-2.0** | v1.18.2 / 2026-08，日更 | 安装版 ~50 MB | ★★★★★ | **首选参考基座**，协议独立成 repo |
| **copyparty** | Python 单文件 | MIT | v1.20.26 / 2026-10-14 | 单 py 文件 | ★★★★☆ | 分块断点续传（up2k）设计值得抄 |
| **croc** | Go CLI | MIT | v11.5.5 / 2026-10-19 | ~10 MB | ★★★☆☆ | 依赖公网 relay，不适合纯局域网 |
| **Syncthing** | Go | MPL-2.0 | v2.1.6 / 2026-10-06 | ~30 MB | ★★☆☆☆ | 是"持续同步"不是"一次性传输"，过重 |
| **PairDrop** | JS/WebRTC | **GPL-3.0** | v1.11.2 / 2026-04 | Web | ★★☆☆☆ | GPL 传染；需信令服务器 |
| **Snapdrop** | JS/WebRTC | GPL-3.0 | 基本停滞 | Web | ★☆☆☆☆ | 大文件不稳、无断点续传 |
| **LANDrop** | C++/Qt | BSD-3 | **2026-03 起闭源** | — | ✗ | **不要作为基座**，仓库已非最新 |
| **Photon** | Flutter | 开源 | 活跃 | ~30 MB | ★★★☆☆ | 只作"极简 UI"参考 |
| **Warpinator** | Python/GTK | GPL | 低频 | — | ✗ | 绑定 Linux 桌面生态 |

### 2.2 关键事实

- **LocalSend 是事实标准**：官方站 70k+ stars，第三方统计已到 ~91k，500 万+ 下载；协议单独开源在 `localsend/protocol`，Apache-2.0 允许商用、闭源分发、修改（保留版权声明即可）。
- **LANDrop 已经闭源**（官方 README 明示"temporarily close source"），很多教程还在推荐 fork 它——这是 2026 年最大的坑。
- **Syncthing 解决的是另一个问题**：它是双向持续同步（适合 NAS 备份），启动配置复杂、常驻内存高，不做"选中文件→点一下→传完"这件事。
- **Snapdrop/PairDrop 类 WebRTC 方案**：免安装属性最好（浏览器直接开），但大文件受浏览器内存限制、无断点续传、需要信令服务器，只能做"应急传截图"，不能做主力。

## 三、协议层：LocalSend v2 值得直接实现

### 3.1 协议骨架

```
端口：TCP + UDP 同为 53317
发现：UDP 组播 224.0.0.167:53317，JSON announce
      （注意：不是标准 mDNS 224.0.0.251，是自建格式）
传输：HTTP(S) REST，三种接口
```

| 步骤 | 接口 | 作用 |
|---|---|---|
| 1. 发现 | `POST /api/localsend/v2/register`（或 UDP JSON 回包） | 双向交换设备信息（alias/deviceType/fingerprint/port/protocol） |
| 2. 协商 | `POST /api/localsend/v2/prepare-upload` | 只传元数据（文件名/大小/sha256），接收端决定接受/部分接受/拒绝，返回 `sessionId` + 每文件 `token` |
| 3. 传输 | `POST /api/localsend/v2/upload?sessionId=&fileId=&token=` | 裸二进制 body，可**并行**调用 |
| 4. 取消 | `POST /api/localsend/v2/cancel?sessionId=` | 中断会话 |
| 反向 | `GET /api/localsend/v2/download` | 发送端起 HTTP 服务，**对方浏览器直接下载**（真正零安装） |

错误码已定义清楚：`401` PIN 错误、`403` 拒绝/token 无效、`409` 会话冲突、`422` sha256 不匹配。

### 3.2 安全模型（可直接照搬）

- 每设备自签 TLS 证书，`fingerprint = SHA-256(证书)`，**证书 pinning** 而非 CA 校验 → 零配置又能防中间人。
- 可选 PIN 码（`?pin=123456`）。
- 反向传输模式强制用 HTTP，因为浏览器拒绝自签证书。

### 3.3 两个已知缺口

| 缺口 | 影响 | 你的机会 |
|---|---|---|
| **无断点续传** | 传 10 GB 断网 = 从头再来 | 加 `Content-Range` 分块 + `.part` 文件 + 服务端记录 offset |
| **无秒传/去重** | 同文件重复传 | 先发 sha256，接收端命中直接跳过（copyparty 的 dedup 思路） |

## 四、库选型（按层拆）

### 4.1 发现层

| 方案 | 库 | 说明 |
|---|---|---|
| **LocalSend 兼容**（推荐） | 标准库 `net.ListenMulticastUDP` | 自己组 JSON，简单，能互通 |
| 标准 mDNS | `github.com/betamos/zeroconf` | 2023 重写，最现代，支持网络切换 `Reload()` |
| 标准 mDNS（保守） | `github.com/grandcat/zeroconf` | 用得最多，但已停更 |
| mDNS（活跃 fork） | `github.com/enbility/zeroconf/v2` | grandcat 的维护分支 |
| **兜底：子网扫描** | 标准库 | /24 网段 254 个 IP 并发 `DialTimeout` 200 ms，1 秒内出结果 |

> ⚠️ 现实：企业 WiFi 常开 AP isolation 或禁组播，mDNS/组播必然失败。**子网扫描是必需品，不是可选项。**

### 4.2 传输层

| 方案 | 结论 |
|---|---|
| **TCP + HTTP/1.1 多连接并行** | ✅ 推荐。千兆零丢包场景下最简单也最快 |
| HTTP/2 单连接多流 | 可选，但对单文件吞吐无增益 |
| QUIC (`quic-go`) | ❌ 不推荐。用户态开销大，macOS 无 UDP GSO，实测 80–90 MB/s vs TCP 107 MB/s |
| 裸 TCP 自定义帧 | 快，但失去 HTTP 生态（浏览器接收、curl 调试） |

**实测参考**（同硬件千兆局域网，2 GB 文件）：

| 传输 | 速度 | 形态 |
|---|---|---|
| TCP (scp) | 107 MB/s | 平稳 |
| QUIC 发送（macOS） | 80–90 MB/s | 锯齿状，每 ~500 MB 掉速 |
| QUIC 发送（Linux，有 GSO） | 103 MB/s | 平稳 |

结论：**局域网没有 QUIC 的用武之地**，别为了技术时髦增加复杂度。

### 4.3 UI 层（免安装硬指标）

| 方案 | 单文件体积 | 额外依赖 | 编译要求 | 评价 |
|---|---|---|---|---|
| **Go + `webview/webview_go`** | **~8–12 MB** | Win10/11 自带 WebView2 | 纯 Go，无需 gcc | ✅ **推荐** |
| Go + Wails v2 | ~12–45 MB | WebView2 | 需 Node（仅前端构建） | 开发体验最好，绑定自动生成 |
| Go + Fyne | ~18 MB | 无 | **需 CGO + gcc** | 纯 Go 栈，但渲染是自绘，观感一般 |
| Rust + Tauri | ~10 MB | WebView2 | 编译慢 | 可选，但生态不如 Go 顺手 |
| C++ + Qt static | 20–40 MB | 无 | 静态编译很折腾 | 不推荐 |
| Python + PyInstaller | 30–60 MB | 无 | 简单 | ❌ 杀软误报率高、启动 2–3 s |

## 五、免安装的 7 个真坑（按踩坑概率排序）

| # | 坑 | 现象 | 对策 |
|---|---|---|---|
| 1 | **Windows 防火墙** | 对方完全发现不了你，程序无报错 | 首次监听时系统弹窗，必须引导用户点"允许"；被拒后检测并在 UI 提示"请在防火墙放行"，别静默失败 |
| 2 | **组播被网络设备拦** | 同一 WiFi 也搜不到（AP isolation / 禁 IGMP） | 三重兜底：子网扫描 → 手动输 IP → 二维码/6 位码 |
| 3 | **多网卡绑定错误** | 有 VPN/虚拟网卡（VMware/Hyper-V/WSL）时组播发到错网卡 | 遍历 `net.Interfaces()`，跳过 `down`/`loopback`/虚拟网卡，每块网卡各起一个 listener |
| 4 | **半截文件** | 传到 90% 断线，留下损坏文件 | 写 `xxx.part`，sha256 校验通过后 `os.Rename` |
| 5 | **文件名非法** | 中文/emoji/`CON`/`NUL`/超 260 字符 写入失败 | 白名单清洗 + 冲突自动加 `(1)` 后缀 |
| 6 | **配置写不进去** | exe 放在 Program Files 或只读 U 盘 | `os.Executable()` 同目录探测可写性，失败回退 `%LOCALAPPDATA%` |
| 7 | **杀软误报** | 静态 Go 二进制被标可疑 | **不要加 UPX**（压缩壳是误报主因）；有条件做代码签名 |

补充：`go build -ldflags "-H windowsgui -s -w"` 去掉控制台黑框并瘦身。

## 六、三条路线

### 路线 A：LocalSend v2 兼容客户端（推荐）

```
Go + webview_go + 自实现 LocalSend v2 子集
```
- 工作量：发现 + prepare-upload + upload + 浏览器接收，约 1500–2500 行
- 收益：**能和手机上的 LocalSend App 直接互传**，不用自己写移动端
- 风险：协议无断点续传，大文件体验一般（可自己扩展，但对方不认）

### 路线 B：自研协议 + 差异化

```
Go + 自定义 TCP 分块协议（断点续传 + 秒传 + 目录树）
```
- 工作量：翻倍，需自己解决移动端
- 收益：断点续传、去重秒传、多文件队列、限速，体验可以超过 LocalSend
- 适合：只做 PC↔PC，用户群固定（如你自己 + 同事）

### 路线 C：fork LocalSend

- 直接改 Flutter 项目加功能
- 缺点：产物 ~50 MB 安装包，**违背"免安装单文件"的核心约束**；Flutter + Rust 工具链较重
- 只在"必须多平台含 iOS"时考虑

### 推荐组合

**先 A 后 B**：用 LocalSend v2 打通生态（第 1 周能跑通传输），再在 upload 接口上加可选的分块续传扩展（对方不支持时自动降级为整文件），形成"兼容 + 增强"。

## 七、待你确认

1. **目标平台**：只 Windows？还是 Windows + macOS + Linux？
2. **是否需要和手机互传**：需要 → 走路线 A（复用 LocalSend App）；不需要 → 路线 B 更自由。
3. **是否要求与 LocalSend 客户端互通**：这是最大的架构分叉点。
4. **是否需要断点续传**：传几十 GB 的 FPGA bit/波形文件时很关键。
